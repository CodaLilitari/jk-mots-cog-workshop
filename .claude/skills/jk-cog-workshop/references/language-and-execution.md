# Writing and reasoning about COG

> Public research edition. This is original authored analysis, not a source-code dump. References marked "retained local evidence" were inspected during research but their raw artifacts are not distributed. Binary identities, measured registries and public package identities are included; source execution and retail gameplay remain different evidence grades.


This guide uses the pinned engine snapshot described in [engine findings](engine-findings.md), alongside measured original-game registration tables. File and line references below point into that snapshot. Grammar and implementation observations are source evidence unless expressly backed by a retail-binary record. Begin with a complete, same-game retail example and its integration resources; COG's resemblance to C is an unreliable specification.

## Script, instance and integration contract

A conventional file contains optional hexadecimal `flags=...`, a `symbols` section ending in `end`, then `code` and another `end`. Symbols may declare `int`, `flex`/`float`, `vector`, `message`, `thing`, `surface`, `sector`, `sound`, `template`, `model`, `keyframe`, `cog`, `material`, and `ai`. The loader recognizes these explicitly in [sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c), lines 45–169. A compiled script is shared; loading an instance duplicates its symbol table and copies its initial flags ([sithCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.c), lines 619–671). Distinguish a script file from the mutable instances using it.

That conventional final code `end` is useful authoring structure, not a proven universal requirement for acceptance. The pinned generated lexer terminates on either `end` or EOF. Two archived code sections lacking final `end` passed the actual parser/codegen probe; appending `end` generated identical words. This does not waive the header's separate `symbols`/`end`/`code` transition or validate incomplete statements at EOF. See custom cases and exact probe scope (retained local evidence).

Nonlocal declared parameters form an ordered level contract. The `world cogs` reader consumes JKL values in symbol-reference order; changing that order changes which input binds to which symbol. `local` declarations retain internal/default values and do not consume a level argument. For resource references, `local` also bypasses ordinary level linking in this load path. It does **not** mean a variable on a C-style stack, nor does it mean the entire script is a local-network COG. See [sithCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.c), lines 408–507 and 533–606; [sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c), lines 865–1087.

`thing`, `surface`, and `sector` references can establish event links. `linkid` is the application-selected link identifier; `nolink` sets it to -1. The default reference mask is `0x401`; the dispatchers compare it to a bit derived from the source thing type, or bit 0 for no source. Use the intended object's type and actual sender path when choosing a mask; it is not a list of message IDs. Relevant code: [sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c), lines 892–923; [sithCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.c), lines 829–850, 1005–1075, 1083–1148 and 1918–1971.

Resource declarations resolve names or indices through type-specific loaders at initialization. Follow the script's role: level COG plus JKL parameters; template COG plus template inheritance and thing flags; inventory/weapon/Force COG plus bin definitions, animations, projectiles and selection lifecycle. A script can parse while referring to the wrong index domain or failing a later resource lookup. The source loader builds a `cog\\<name>` path; mount precedence is an integration property to verify in the chosen installation, not a property of an arbitrary loose file on disk.

## Grammar and expression behavior

Read [cog.y](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/cog.y) and [cog.l](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/cog.l) alongside the actual generated [y.tab.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/y.tab.c) and [lex.yy.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/lex.yy.c), with [sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c) for symbol and bytecode generation. Generator settings matter: although `cog.l` writes keyword literals in lowercase, the pinned generated lexer's `yy_ec` table maps each ASCII uppercase/lowercase pair to the same class. The existing custom-script probes accept mixed-case `Return`; lowercase keywords are a consistent authoring convention, not a rejection rule for this generated lexer. Identifier lookup separately lowercases symbol names (lines 717–744).

When an identifier is absent from the local and global symbol tables, that lookup can add a new local symbol initialized to float zero, subject to capacity. An undeclared name is therefore not automatically a grammar error. It can still indicate a typo, a wrong initial type/value, missing resource loading or an undocumented integration dependency. Explicit declarations and initialization make authored behavior reviewable. In particular, a newly inserted identifier is not automatically a registered native function; availability and actual callable type must be checked separately.

- The grammar supports labels, braces, expression statements, `if`/`else`, `while`, `do`/`while`, `for`, `goto label;`, `call label;`, and `return;`. `stop` lexes as `return`. There are no user-defined C functions with parameter lists or local lexical scopes. A label does not automatically stop fall-through; end each intended handler/subroutine path explicitly.
- `break`, `continue`, and `switch` statements are not supported productions in this grammar. `break` and `continue` have lexer rules but no working statement production; `switch` is not a keyword rule in the captured lexer. It has no `++`, `--`, compound assignments, ternary operator, struct members, casts, pointer arithmetic, or C declarations inside `code`. Write `i = i + 1;` and explicit conditions/labels as appropriate. Do not confuse a lexer token's existence with a working grammar production.
- Integer literals support hexadecimal and leading-zero scanning with `%i`; avoid leading zeros for ordinary decimal values. Floating literals support fractional/exponent forms. A vector literal uses single quotes, for example `'0 0 1'`; ordinary strings use double quotes. Use `#` or `//` line comments. The captured lexer has no C `/* ... */` comment rule.
- Arithmetic, comparisons, bitwise `&`, `|`, `^`, logical `&&`/`||`, unary minus, logical `!`, assignment and indexed-symbol expressions exist. Although `~` is a lexer token, it has no unary production here. Use documented bit verbs where appropriate.
- **Do not rely on short-circuiting.** The grammar generates both operand subtrees followed by a logical operation, and the VM pops both values. Therefore `valid && DangerousCall()` is not a safe guard against that call. Write nested `if` statements. This follows [cog.y](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/cog.y), `logical_and_expression`/`logical_or_expression`, [sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c), lines 829–835, and [sithCogExec.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogExec.c), lines 1255–1267.

The VM uses tagged stack values rather than a C static type system. General arithmetic in the inspected implementation pops floating values; many engine verbs convert to integer/resource handles. `PopInt` truncates a float by integer conversion, while its empty/unsupported fallback is -1; `PopFlex` returns 0 on failure. Variable assignment copies a value's runtime tag. The assignment opcode consumes its operands without pushing an expression result. Use a comparison as a condition; do not assume C-style assignment expressions or chained assignments produce a usable value. Thus an `int` declaration does not establish C-style integer arithmetic for every later expression. Inspect [sithCogExec.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogExec.c), lines 161–222, 406–454 and 1286–1324. These details also mean a missing argument may consume unrelated stack data instead of producing a useful compile error.

The captured VM sends `!=`, `&&`, `||`, unary `!`, and conditional branches through integer-pop paths, whereas `==` and ordering comparisons use floating-pop operations. By source interpretation, `if (0.5)` takes the false path after truncation, and `0.25 != 0.75` compares two integer zeroes. Prefer explicit comparisons such as `value > 0.0`; for a fractional inequality, negate the boolean result of `a == b` or choose an explicit tolerance comparison. These are concrete current-source cautions, not independently executed proofs for all original VM versions. Anchors: [sithCogExec.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogExec.c), lines 209–231, 431–454 and 1255–1324.

Arguments are emitted left to right and engine implementations pop them in reverse. To derive a verb signature, read the complete implementation, reverse its unconditional pop sequence, inspect mode/flag-dependent branches, and identify whether all return paths push a value. A wrapper can alter the interpretation. `implementation_index.json` helps locate this code but cannot replace that inspection.

`ReturnEx(value)` sets the message response without itself leaving the current code path. `Reset()` clears the call depth in the pinned source; a following `return` therefore ends the pass instead of resuming a nested `call` site. Inspect `sithCogFunction.c`, lines 424–427 and 692–695, and `sithCogExec.c`, lines 1218–1235. This is a pinned-source contract, not fresh original-retail execution.

The grammar allows general postfix-call syntax without checking whether the target is a native function. The pinned VM's `CALLFUNC` path checks for a symbol ID and a pointer-valued function symbol; a missing/non-function target does not execute a native verb, and the failure branch leaves its already-pushed arguments in place ([sithCogExec.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogExec.c), lines 120–159). Likewise, a void verb pushes no numeric result: an enclosing expression can consume outer-call operands, rather than receive a guaranteed zero. `ClearActorFlags` used in arithmetic in the custom force-well example demonstrates the source-contract issue. These are source observations, not an original-retail VM execution result; see custom cases (retained local evidence).

`base[index]` indexes consecutive symbol IDs; it does not allocate a conventional array or check an array length. Preserve declaration adjacency for scripts using the traditional consecutive-symbol technique and bound the index. The opcode adds the index to the base symbol ID ([sithCogExec.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogExec.c), lines 100–118). `HeapNew`, `HeapSet`, `HeapGet`, and `HeapFree` offer a separate per-instance heap; its lifetime and target-specific implementation still need review ([sithCogFunction.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogFunction.c), lines 935–1001).

## Message context: five identities and four parameters

| Accessor | Meaning in the dispatch structure | Common mistake |
| --- | --- | --- |
| `GetSenderRef()` | Index/reference of the thing, sector, surface or COG sending the event | Treating it as always the player |
| `GetSenderType()` | Domain of sender reference; common values: thing 3, sector 5, surface 6, COG 9 | Using a surface index in a thing verb |
| `GetSourceRef()` | Dispatch-specific originating source reference | Assuming it is identical to sender |
| `GetSourceType()` | Domain of that source | Ignoring absent/system sources |
| `GetSenderID()` | Link ID passed to this handler; for extended timer events, the timer ID | Confusing it with a thing index or network player ID |
| `GetParam(0..3)` | Four message-specific floating parameters | Treating them as universally defined or persistent |

The getters directly read instance fields ([sithCogFunction.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogFunction.c), lines 41–64 and 697–711). Dispatch assigns these fields before execution ([sithCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.c), lines 1275–1294 and 1415–1436). Sender/source numeric domains are in [types_enums.h](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/types_enums.h), lines 787–796. For example, an activated linked surface uses that surface as sender and the activating thing as source. The exact producer of another message may differ, so trace it rather than generalizing the example.

`SendMessage(targetCog, message)` sets sender type to COG and sender reference to the caller's COG index, forwards its current source fields and uses link ID 0. `SendMessageEx(targetCog, message, p0, p1, p2, p3)` additionally provides four values and returns the receiving handler's return-value field ([sithCogFunction.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogFunction.c), lines 532–554). `ReturnEx(value)` sets that field; it does **not** execute a VM return, so follow it with `return;` if execution should end (lines 692–695). The dispatcher uses a negative sentinel when a handler is absent/disabled, and remote forwarding has a different immediate return path; a synchronous local return is not a network RPC guarantee.

To receive an ordinary event through the script's handler table, declare its `message` binding and provide the corresponding executable label. A constant used by a sender does not need a receiving label in that sender's script, and a plain internal subroutine label does not need a message declaration. A registered message constant is not automatic event delivery; linkage, inventory bin assignment, class binding or explicit send still supplies the route. Same-ID aliases such as `activate`/`activated` should not be treated as independent events.

Check missing and duplicate labels separately from unknown message spellings. The code generator writes label locations into a table; repeated occurrences of one label ID overwrite the earlier location, and handler binding reads that table after parsing ([sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c), lines 155–160 and 781–827). The custom Kyle and IR-goggle sources contain repeated `damaged` and `activated` labels. They passed the code-section parser probe; that does not validate their dispatch contract. Missing internal `call` labels are another case: the label table starts at `-1`, so unresolved branch targets require review rather than an assumption that a label-call failure behaves like a failed native call.

The symbol parser also supports a message-name alias: `message onStart=startup` binds the local label `onStart` to the registered `startup` value. Validate that right-hand value against the game registry and the left-hand label against code; do not reject a valid alias merely because the label name is absent from the engine's global messages. See [sithCogParse.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogParse.c), lines 1089–1112.

That parser lookup uses the generic global symbol table, not a message-only table. Both inspected original executables also register zero-initialized float symbols `global0` through `global15`; see retail_float_globals.json (retained local evidence). The source parser copies a found symbol's raw value into a handler ID without verifying its type. Consequently `message global0` is not an unknown global spelling, but neither is `global0` an ordinary integer message constant or proof that the engine will dispatch a useful event to it. Keep integer-message availability, other-global binding and event delivery as separate findings. Do not use an incomplete editor word list as the language specification.

## Sleep, timers, reentry and lifetime

All handlers in one COG instance share symbol values, heap and message-context fields. `local` does not give each invocation a private copy. `Sleep(seconds)` sets the current execution state to sleeping with an absolute millisecond timeout. The executor can enter another message while that instance is running or suspended; the call stack saves execution position, execution state, wake time and trigger ID, **not** arbitrary symbols or sender/source/parameter fields. See [sithCogExec.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogExec.c), lines 289–319 and 1198–1231; [sithCogFunction.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogFunction.c), lines 82–112.

Capture needed event data before suspension, but remember another handler can overwrite that same capture variable. Use a busy/state guard for one outstanding action, explicit per-object/per-request storage for concurrent work, or a timer/state-machine design. Revalidate a saved thing reference after sleeping: object removal and index reuse can invalidate its original meaning. Do not assume a delayed `GetSourceRef()` still refers to the activating player.

`SetPulse(seconds)` controls the instance's repeating pulse; nonpositive values disable it. `SetTimer(seconds)` controls one simple pending timer slot and replaces it; nonpositive values cancel it. `SetTimerEx(seconds, id, p0, p1)` schedules an extended timer event and supplies its ID through `GetSenderID()` and payload through `GetParam(0/1)`. The captured `KillTimerEx` only searches for IDs greater than zero, so choose positive IDs when cancellation matters. See [sithCogFunction.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogFunction.c), lines 317–421 and [sithCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.c), lines 1704–1773.

Disabling a pulse or timer does not return from the current handler. The M.A.C jet-pack exhaustion branch continues into sound/motion operations after `SetPulse(0)`. Use an explicit `return;` when cleanup should end that invocation. A requested pulse interval is not a guaranteed delivery frequency: the pinned processor sends at most one due pulse per processing call and schedules from current game time. Fractional-time wrap, long frames and repeated events need their own timing/lifecycle checks.

`call label;` uses the same shared symbols and a four-frame call stack in this source. Avoid deep nested calls and recursive message sends. Ordinary `return;` unwinds that stack or stops the current handler. Sleeping timing follows game ticks; it is not a precision real-time scheduler. The source's additional fixed-timestep adjustment is build-dependent and should not be promoted to a universal measured retail timing rule.

## Multiplayer: execution location and transmitted effects

The pinned dispatcher executes startup/shutdown locally, executes normal messages on the server or in single-player, and executes a COG marked local on the receiving peer. For an ordinary nonlocal COG on a client it forwards non-timer/non-pulse messages to the server; it does not forward those periodic events. The fork has additional co-op exceptions. See [sithCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.c), lines 1247–1299 and 1386–1457. Template binding can add class/local flags before this decision, as described in [engine findings](engine-findings.md).

The `0x40` script flag concerns local execution. The separate `0x200` no-sync bit participates in many verb-specific outgoing-state guards; `0x240` combines the two. The source macro `COG_SHOULD_SYNC` additionally checks for an output stream and excludes startup/shutdown ([sithCog.h](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCog.h), line 56). Some verbs explicitly transmit by another route. For example, `SendTrigger` directly uses the COG network send path; blanket claims that every call in a `0x240` script is silent are false for this source.

`SendTrigger` supplies an application-defined protocol number through the trigger event's source reference, plus four parameters. A local target player causes local dispatch; a remote target player sends to that peer; the no-target path broadcasts and executes locally ([sithCogFunction.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Cog/sithCogFunction.c), lines 1197–1252). Use an explicit protocol contract, validate payloads and prevent duplicate authoritative effects. Sending damage or spawning on every client can multiply the intended operation.

Thing indices and network GUIDs are different. The COG transport converts typed thing sender/source references into GUIDs and resolves them back on reception. The four generic float parameters are transmitted as floats, without automatic “this parameter is a thing index” conversion. If a protocol carries an object in a parameter, define and implement the identification convention yourself. See [sithDSSCog.c](https://github.com/CodaLilitari/OpenJKDF2-MotS-Fixes/blob/b1be98bd4f170b5384cb71b15443a274aac6a937/src/Dss/sithDSSCog.c), lines 10–111. Its COG-state serialization is a separate path, with different type and synchronization handling; it is not evidence that every local variable change immediately replicates.

For each requested behavior, decide who owns gameplay state, who receives the visual/audio result, how clients identify objects, what a late join must reconstruct, and how repeated events and cleanup are handled. Then test the chosen path on connected clients. Use same-game stock examples to establish contracts, and keep lexical checks, source probes, binary analysis and observed multiplayer behavior as separate validation levels.
